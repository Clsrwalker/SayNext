**SayNext EvenHub v2 小步修复方案 — 2026-09-04**

状态：方案阶段，未开始实施。基于当前 v0.2.85 工作区及 [31 项审计问题](./evenhub-v2-audit-2026-09-04.md)。用户已确认：仅本人及自己的设备使用；九类问题均要修复，先整理方案，控制改动范围及回归风险。

**实施原则**

采用“一个根因一份补丁、每批可独立验证、相关前后端一起发布”的方式。继续使用现有 React/useState、Even SDK、Bun/Hono、SQLite、STT provider 和模型配置。优先复用现有 connection-recovery、conversation-audio、renderer、会话详情接口和数据库字段。

本轮以修复可靠性和补齐已列出的功能为范围。App/runtime 不整体重写，SDK/框架/模型版本不与修复一起升级；常规提示词、推测生成策略及识别阈值也不顺手重调。确需修改的材料漏传会单独成批验证。多人账号、跨服务器无缝续录、完整事件日志系统、独立任务管理数据库不作为本轮前提。

目前有大量已有未提交修改，实施基线必须包含这些修改及相关未跟踪源码，不能从 HEAD 创建一份缺失现有工作的旧基线。密钥、真实数据库、日志正文不进入提交或普通代码备份。每批只提交明确的文件，避免 git add 全仓触发无关变更；现有 main/dev push 会触发部署，验证阶段使用独立分支。

**预先确定的交互规则**

| 操作 | 建议行为 |
|---|---|
| 打开应用 | 显示待开始；用户主动开始后才采集。 |
| 会话中返回首页 | 会话继续，首页明确显示当前会话、采集状态、暂停/结束入口；原开始按钮变为“返回当前对话”。 |
| 离线点击开始 | 显示“连接后开始”并允许取消，初始化与连接未完成时不开麦。 |
| 开始尚未确认时点击结束 | 记住取消意图；若随后收到 started，只结束该会话，不再开麦。 |
| 离线点击结束 | 立即停止本机采集，显示“已停止采集，等待保存”；保留待确认的结束请求，重连后补交。 |
| 普通 WS 短暂重连 | 依据当前用户采集意图恢复；用户已经暂停/结束时不得重新开麦。 |
| WebView 重建或应用重开 | 先核实会话、恢复内容，以暂停待继续方式进入；用户点击继续后开麦。不能仅持久化一个永久 sessionId 就自动接管。 |
| 后端进程重启 | 保住已经落盘的内容，将无法续接的旧会话明确标为异常中断；本轮不承诺继续原 STT/AI 连接。 |
| 关闭自动弹窗 | 继续保存 AI 提示，允许主动打开详情；主屏不自动展示新提示。 |
| 提示时长 | 控制主屏自动提示；主动打开的详情不被到期计时强制关闭。 |
| 分享至速记 | 暂按“保存为现有应用内笔记”实现：生成可编辑草稿，用户保存后写入；默认不选作下一场 AI 材料。当前没有独立速记模块。 |
| 地点 | 有真实数据才显示，没有数据时隐藏固定地点。 |

这些规则给出本方案的可验证目标。“分享至速记”若实际指系统备忘录或其他外部应用，需要另定目标接口；当前方案先复用本应用笔记。长内容翻页手势需通过 G2/R1 真机验证后确定，不能让同一手势同时触发原生滚动与应用翻页。

**S0：先建立可靠基线**

- 留存当前源码状态、已有安装包、前后端版本/构建哈希以及数据库备份位置；在实施时核实实际运行的是 Local 还是 VPS，避免两边同时写入或测错版本。
- 现有审计测试中有“断言错误确实存在”的用例。修复某一项时，将对应复现转为“断言正确行为”的正式回归测试；尚未修复的证据保留，不用全部变绿来冒充已经修好。
- 当前参考基线为前端 136 项、当前后端定向 171 项通过；它只是此前审计结果，实施开始时重新确认一次，不当作实施后的结果。
- 独立修正 `src/server/api/evenhub-v2.ts` 的三个类型收窄错误，保持非法参数 400、合法参数原有行为，作为后续类型检查的干净基线。

验收：现有工作没有丢失；能够重现关键故障；前后端类型检查均可作为后续门槛。S0 不改变数据库结构。

**S1：先把公网入口保护完整**

采用“每台自用设备一份授权凭证”，保留现有历史 owner ID，无需新账号系统或凭证数据库。

1. 在受控环境生成高熵随机 device_token；服务端配置保存 hash、设备名及有效期，映射到现有数据 owner。本人一次性将凭证粘贴到现有设置页的“设备授权”。长期凭证不进入 ehpk、VITE 构建变量、普通会话设置同步、URL 或日志。
2. REST 通过统一请求封装发送 Bearer；服务端由同一鉴权模块验证，得到可信 owner。禁止 query/body 的 userId 改变授权归属，也不能将 SDK 返回的 uid 当作验签过的身份。当前 SDK 未提供可据此直接验证请求的身份 token。
3. 浏览器 WS 无法像 fetch 一样设置任意 Authorization 头，使用一个新增的已鉴权接口 `POST /api/evenhub/v2/auth/ws-ticket`：凭 Bearer 换取约 30 秒、一次性的随机票据，绑定设备、owner、clientSessionId，再用 ticket 建立 WS。票据使用有上限的内存缓存，过期/重复消费拒绝。长期 token 不放 WS URL，票据日志也做脱敏。
4. 配置撤销/过期必须使对应旧连接失效；初版若通过服务重启应用凭证配置，旧连接自然断开后必须重新验证。401/403 在首页显示重新授权，停止无意义的两秒重试。没有配置凭证时服务应拒绝敏感访问，不能退回匿名模式。
5. 凭证存储与普通 settings 分开。可以使用宿主存储，但本地 SDK 未声明它是系统安全钥匙串，不能承诺加密。提供仅本次使用的内存方式；任何 storage getter/read/write 失败都可见且可降级，不导致白屏。
6. 凭证接入前，将 backend origin 解析改为精确可信地址及显式开发地址，移除“域名包含 saynext.”或任意端口 3000 即可信的判断，防止发送到错误目标。CORS/WS Origin 按真机实际值收窄；若宿主确实使用 null Origin，再显式兼容，身份验证仍强制执行。
7. 同批检查共享 `/api/prenotes` 及其详情/chunks/写入子路由。它们与 v2 使用同一个 conversationLogger，旧 handler 直接读取 query userId；只保护 v2 不足以关住同份笔记。复用经过验证且 owner 匹配的现有 Mentra 身份，或将不用的旧敏感入口限制为本地管理访问。相关 export/memory 管理入口也要核对数据归属，不能以 v2 路由测试通过替代旁路检查。
8. 保护范围明确列出，保留现有 Mentra 登录和 SDK webhook 的正确签名验证路径，不把设备密钥中间件无差别套到所有回调。CORS 不是身份验证；仅修改 CORS 不算完成。

主要边界：`routes/routes.ts`、`api/evenhub-v2.ts`、`evenhub-v2/ws.ts`、新增小型服务端 auth 模块，前端 `evenhub-v2-client.ts`、settings 授权输入及独立存储封装。共享笔记入口只接必要身份检查，不重写 CRUD。

验收：匿名/错误凭证无法读写 REST 或建立 WS；合法设备仍可读取原历史、开始和保存；伪造 userId 无效；票据过期/重用无效；撤销后旧连接不能继续发送音频；旧 Mentra 正常通路仍通过；ehpk 及日志不含凭证。

发布：服务端、新安装包、本人设备凭证一起准备，在受控环境验证后于同一窗口切换。旧包不提供匿名兼容。若切换故障，保持访问门禁或暂时关闭敏感入口；安全回退不得恢复已知匿名公网暴露。

**S2：先修超时，再修 AI 任务生命周期**

拆成两份补丁：

- S2a 覆盖请求全过程：保留原超时配置，将 fetch、错误 response.text、成功 response.json/text 包在同一 try/finally，最后才清理 timer 和 abort 监听。涉及共享 `local-llm/openai-json-client.ts` 和 v2 `openai-conversation-client.ts`。本补丁不添加 AI 自动重试，避免改变费用和输出次数。
- S2b 固定任务归属：每个 job 在创建时捕获 conversationId、生命周期版本、settings/笔记快照和 provider lifecycle。所有 await 返回后以及发布/落盘/commit 前校验归属；结束时失效并释放本场 AI 所有权。旧 finally 只能清自己的引用，不能清新任务。队列遇重复项继续取下一项，直到找到可运行项或队列为空。

主要边界：上述两个请求客户端、`evenhub-v2/runtime.ts`。先做局部 helper 和明确引用检查，不整体改写生成器。

必须保留：AI 取消和 STT 尾句处理是两个不同边界。隔离旧 AI 时不能把 stop/final flush 期间最后一个有效 STT final 丢掉；继续保留 partial 不进入正式转录/总结、已显示 cue 保存，以及现有推测生成业务规则。

验收：响应头已经成功但正文挂起仍能超时/取消；A 生成中结束并开始 B，B 正常生成，A 的迟到成功、失败和 finally 均不污染 B；router/context/provider 创建迟到也安全；A/A/B 的 B 无需额外语音触发就可处理。共享 OpenAI 客户端的其他调用点一起回归。

**S3：把开始、返回、暂停、结束接成一个可靠流程**

这批前后端成对修改，复用现有 envelope 的 requestId/conversationId，不换协议框架。

- 在现有 `connection-recovery.ts`、`conversation-audio.ts` 中明确启动/停止意图与已确认状态，减少互相矛盾的判断入口。`settingsReady` 当前在失败 finally 也变 true，需另以 bootstrap 成功作为初始化依据。
- bootstrap 成功、有效授权、WS ready、SDK 可用后才提交启动；等待期间不开麦，用户可取消。点击连发复用同一个启动请求 ID。WS onopen 只进入握手，先确认当前 ready，再处理待提交命令；重复 ready 不重复执行意图。
- 已有会话时，首页提供返回及暂停/结束入口，保持采集状态可见。
- 结束立即更新本地采集意图并关麦，保留 `{requestId, conversationId, pendingEnd}`。服务端确认前不能清掉它并开始另一场。start 已发但 ID 未返回时结束，迟到 started 只用于补发 end。
- 重连优先处理 pendingEnd，其次处理仍有效的 pendingStart。started/saved/error 回应关联原 requestId；对同一个 start/end 重复提交采用有界幂等记录，不能重复创建会话或总结。连接丢失或服务重启后超出幂等缓存范围时，先查实际状态再重发。
- WS 的文本与 PCM 入口同时检查当前 connId；控制命令必须匹配会话 ID。被替换的旧连接失去输入权限，旧 close 也不能销毁新连接。
- 沿用 bridgeAudioCommandRef：每个 await 前后、每次 true 开麦前检查当前 bridge、会话、命令版本和用户意图。旧 true 已在途且无法取消时，返回后必须补 false，保证暂停/结束后的最终原生命令为关闭。

主要边界：前端 App、connection-recovery、conversation-audio；后端 ws、runtime；前后端协议类型中的必要可选关联字段。存储读取降级 F28 在接入授权/启动流程时一并落地。

验收：慢启动不漏笔记；连点只建一场；返回首页不会丢控制入口；断网开始可取消；断网结束即时停本机采集，重连后只保存一次；结束发生在 started 之前也不会重新开麦；任何旧连接/错会话命令均不生效。

**S4：补齐 Deepgram 实现，而不是更换识别服务**

在现有 Deepgram adapter 内补 desiredRunning、socket generation、握手超时、可取消重连和有界 PCM 缓冲，接入已经存在的 onConnectionState。借鉴 AssemblyAI 的行为契约，但不把两个 provider 重构成新框架。

会话语言保存在 start(options)，初连/重连一致使用。English/Chinese/Auto 的具体 Deepgram 参数需以实际官方支持和账户模型验证，不能把 AssemblyAI 的省略参数规则直接照搬。缓冲上限按音频格式换算为时长/字节，断线时保留最新数据并报告丢弃量；不承诺网络中断期间零音频损失。

首个有效 PCM 到达后，按当前故障类型清除 no_audio，而不是检查 timer ref 是否仍存在。状态分别表示 SDK 开麦、收到 PCM、STT 是否连接，避免一个 listening 掩盖上游断线。

主要边界：共享 `evenhub/stt.ts`、runtime 状态回调、App 音频诊断。共享文件必须覆盖旧 EvenHub/v1 的受影响行为。

验收：异常断线可恢复；主动暂停/结束后不重连；旧 socket 事件不影响新连接；send 抛错/握手挂起都有退出路径；音频缓冲有上限；语言重连保持；三秒后首包迟到能清错。真实语言识别与后台切换留到真机验收。

**S5：重连补数据，异常退出能收尾**

拆成两份补丁，先做连接恢复，再做终态收尾。

- S5a 使用已有 `GET /conversations/:id` 补齐 final transcript、cue、summary，并刷新历史以弥补丢失的 saved 通知。按稳定 ID 合并；恢复请求绑定当前连接和会话版本，避免旧 GET 覆盖新会话或新的 WS 状态。同一 transcript ID 可能修订，不能只做简单数组去重；快照期间缓冲实时更新并按明确的快照边界/修订版本合并。若现有字段不足，增加最少的可选快照序号或修订字段，暂不建设持久事件重放系统。
- 仅保存必要恢复信息：sessionId、目标 conversationId、待确认控制请求及用户意图，不保存原始音频。页面重建后先核实 owner/会话状态，默认暂停待继续。不同页面不能无提示抢占同一会话。已在数据库的内容可补齐，断网时从未到达服务器的音频不能凭快照恢复。
- S5b 让正常结束、TTL 到期、graceful shutdown 复用可重复调用的收尾方法。先停止采集并保留尾句处理，可靠落盘终态和总结排队，再做有超时的上游清理。保留 `queueSummary → conversation_saved → enqueue` 顺序；落盘失败不假报 saved。
- TTL 清理等待收尾结束再删除 cache，并处理“到期同时重连”的竞态。进程重启扫描没有 runtime 的遗留 active，复用现有 abandoned 状态和已保存 final 内容。硬崩溃无法获知准确停录时刻，不把重启时间伪装成真实持续录音时长；依据最后可确认活动保守显示，异常中断单独标识。
- 运行中 active/ending 会话明确拒删，返回可解释错误；比删除操作暗中停止录音再删除更容易验证。

主要边界：client、connection-recovery、App；ws、runtime、store、详情 API、index。优先复用现有字段；需要新的持久化字段时单独评估可空的增量迁移，不把迁移夹进一般补丁。

验收：短断线后已落盘内容完整且无重复；快照期间新转录修订/新 cue 不被覆盖；丢失 saved 后历史仍恢复；旧快照不切换当前记录；TTL 与重连同时发生可收敛；退出/重启无无解释的 active 孤儿；拒删当前会话后转录保存继续正常。

**S6：总结、材料和错误反馈分别修**

- S6a 材料一致性：canonical/stateless/speculative/fallback 都使用本场固定的选中笔记快照；prenoteUsedIds 只记录实际进入请求的材料。只修传递路径，保留其余生成策略。以唯一标记检查每条最终请求构造，不能只验证配置里存在笔记 ID。
- S6b 总结恢复：在请求总超时已修复后，增加可停止的周期扫描和有限并发消费，处理所有 queued，不只前 100 条。利用已有 attempt_count/started_at 作为 claim 版本；完成/失败更新必须匹配本次 claim。扫描不重置当前进程正常 inFlight，旧结果不能覆盖新的重试。
- 新增已鉴权 `POST /api/evenhub/v2/conversations/:id/summary/retry`，仅把允许重试的 failed 原子转 queued，连点幂等；ready 不自动重算。失败原因区分不可恢复配置/鉴权与暂时网络故障；如添加自动重试，只针对暂时故障设置次数和退避上限，保留手动重试入口，避免无限花费。
- S6c 页面错误反馈：bootstrap、笔记保存、设置同步、历史加载各有局部 loading/error/retry。保存失败保留草稿；设置失败保留本地值并标“未同步”。请求超时覆盖 body；历史查询带 request generation 和取消信号。轮询上一请求完成再排下一次，切页后不改当前选择。
- failed 总结显示重试按钮；queued/running 显示真实服务器状态。前端不凭自身等待时间擅自把后端 running 改 failed。

主要边界：context-adapter、auto-cue-generator；summary-runner、store、API/routes、index；App、client、settings-storage。三份补丁分别验证，不与模型质量调参混合。

验收：所有生成路径使用笔记；启动时未达到 stale 阈值的总结之后仍能恢复；积压超过 100 条也继续消费且并发有界；旧任务不覆盖新 claim；失败重试只执行一次；A 历史慢/B 历史快不跳回 A；初始化失败可见、重试能恢复，草稿不丢失。

**S7：眼镜显示和操作的小补丁**

1. 订阅所有权：连接开始时就确定 owner，旧异步 startup 只能清理自身订阅；原生 startup/rebuild 有序执行。保留 StrictMode，用测试防止重复连接，而不是删除 StrictMode 隐藏错误。
2. 初始化补绘：复用现有 createGlassRenderer，初始化和后续渲染走同一调度路径；等待后重新读取最新目标，完成哪个页面才提交哪个 rendered state。保留已验证的文本升级/渲染失败恢复。
3. autoPopup：只控制主屏自动展示，主动菜单详情仍可访问；关闭后立即隐藏自动提示。
4. cueDuration：为当前自动提示建立可取消的到期 timer，新 cue 替换旧 timer，forever 无 timer，结束/卸载清理。采用真正展示后的时间作为时长起点，避免绘制延迟占掉阅读时间；主动详情不被到期关闭。
5. 退出：区分“打开退出确认页”和“确认退出”两种 effect。取消回原视图；确认先执行可靠停止/保存意图，再调用 SDK shutDownPageContainer。加入已关闭标记，防止 glassPage effect 随后自动重建；调用失败可重试，不显示假成功。

主要边界：glasses-bridge、glasses-renderer、glasses-layout、glasses-state、glasses-event-controller、types、App 的对应 effect。订阅、绘制、显示设置、退出至少分为独立补丁。

验收：A/B startup 乱序后恰好一个有效订阅；卸载后零订阅；初始化等待期间的新 cue/结束最终正确呈现；无新语音也按时隐藏；旧 timer 不清新 cue；取消退出不陷入未录音 main；真正退出只调用一次，之后不自动重建/采集。
